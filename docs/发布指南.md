# 发布指南

把打好的包传到 [twilitrealm.dev](https://twilitrealm.dev/mods/) 时要注意的事。包格式与客户端行为以官方为准：[modding.md](https://github.com/TwilitRealm/dusklight/blob/main/docs/modding.md)。

## 包和站点条目

- 包就是 `dist/` 目录里那个 `.dusk` 文件，本质是个 zip：`mod.json` 记元信息，加上 mod 自己的文件
- 站点上一条 mod 叫做`条目`。包里的 `mod.json` 里的 `id` 决定包挂在哪条条目下
- `id` 就是包的唯一编号，发布之后改 `id`，等于新开一条 mod
- `mod.json` 里的 `version` 字段用于标识 mod 的版本，字段变化时站点就视为发布了新的版本

## 要传哪些文件

`dist/` 里就是最终用于发布的 mod 包，打包配置写在 `scripts/config.default.json`
- `config` 的 `langs.zh-Hans` 里按语言分成若干项目，一个项目包含了各个分包的配置：源素材、列名、地区、元信息
`id` / `name` / `version` / `description` 都写在这一块的 `mod`（普通版）和 `mod_origin`（保留游戏原字库位图的那版）里，
新版本号也改在这里。包名跟着 `id` 走，`id` 改了包名也跟着改。

`icon` / `banner` 的源图放 `assets/`，打包时由脚本按官方格式写进包内 `res/`（缩进 / 字段顺序 / 末尾无换行 / UTF-8 无 BOM 都由它保证）。

## 传之前先跑一遍本地检查

```
python scripts/build_sjis_pack.py --check
```

它按站点限制核元信息和图片，不通过就不写包

### 站点与客户端的限制

这份清单是上传踩过的坑攒出来的，能挡掉大部分「传上去被拒」

- `id`：只能用小写字母、数字、下划线、点；首尾不能是点；不能有两个连续的点。**发布之后不能改**（站点拿它当主键）。
- `description`：最长 265 个字符，只能写一行，里面不要放链接（链接填到站点的 Source 字段）。
- `name`：最长 48 个字符。
- `version`：写成 `X.Y.Z`（三段数字），发新版往上加。客户端会拿包里的 `id` + `version` 跟条目核对，对不上就不认。
- `icon` / `banner`：不是必须的。不给图，站点列表里显示名字的首字母占位；站点会自己从包里取图。
- 包最大 5 GB。

## 必须手工填写的信息

- 分类（Utility / UI）
- License
- Source URL
  - 比如 GitHub 仓库地址
- 截图
- changelog
- 描述正文
  - 安装说明、致谢、AI 声明这类长文
  - 注意：长文本不要塞进包里的 `mod.json`

## 上传

- 游戏有欧版、美版、日版三种盘，本站每个地区各出一份包
  - 三份包的 `id` 都不一样，所以在站点上是三条
- 换语言同理：`id` / `name` / `description` 整个换一套，站点上是新条目，可以和原来那条共存
- 已经在站点上的条目发新版：`id` 不动，只加 `version`，重新打包后传到原条目
