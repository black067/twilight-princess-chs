# 发布指南

`dist/<id>.dusk` 上传到 [twilitrealm.dev](https://twilitrealm.dev/mods/) 的注意事项

包格式与客户端行为以官方为准：[modding.md](https://github.com/TwilitRealm/dusklight/blob/main/docs/modding.md)

## 校验

本地闸门：`python scripts/build_sjis_pack.py --check`（只校验元数据 + 图片，闸门在 `check_meta()`）。

本站与客户端上已实测/已确认的限制：

- `id`：小写字母 / 数字 / 下划线 / 点，首尾不能是点、不能有连续点；**发布后不可改**（catalog 主键）。
- `description`：≤ 265 字符（站点已收录 summary 的最长值），且为单行、无链接——它是 mod 页摘要，链接填站点的 Source 字段。
- `name` ≤ 48 字符；`version` 形如 `X.Y.Z`，更新时递增（客户端按 `id` + `version` 校验包与条目一致）。
- `icon` / `banner` 非必需：缺图时列表显示首字母占位；站点从包里取图。
- 上传上限 5 GB。

## 参数

lang 段的 `mod` / `mod_origin` 就是全部元信息（见 `scripts/config.example.json`）；图填 `assets/` 里的
源图，打包时由 `build_sjis_pack.py` 按官方格式写进包内 `res/`（缩进 / 键序 / 末尾无换行 / UTF-8 无 BOM 都由它保证）。

## 发布时的内容

- 分类（Utility / UI）、License、Source URL（GitHub 仓库地址）、截图、changelog。
- 长文（安装说明、致谢、AI 声明）放页面的描述正文里，不要塞进 `mod.json`。

## 包与版本

- 一个 lang 段在一个地区出一份 `dist/<转义 id>.dusk`；中文段（`langs.zh-Hans`）是对外发布的
  `dist/yiga_zh_hans_<region>.dusk`（`<region>` = us / eu / jp），共 3 个包，各传各的（id 不同、互不覆盖）。
- 换语言 = 换 `--lang`：id / name / description 都写在该 lang 段的 `mod` 里，包名跟着 id 走
  （`.` → `_`），不同语言的包能共存在 `dist/` 里。
- 发新版：改该 lang 段里的 `version` 后重新打包上传；**id 不能变**（改了等于换一个 mod）。
