# 构建指南

1) 克隆本仓库 `twilight-princess-chs`

2) 自行准备：游戏数据（消息库与两套字库归档）、`assets` 里的 icon/banner（用于 mod 显示）、两套字体文件

- `fonts.fontres`：游戏里画对话正文、菜单、栏位文字的那套字库
- `fonts.rubyres`：游戏里画存档界面、地图菜单楼层与地名、Game Over、对比度页面的那套字库

3) 生成索引与译文表（换素材或换语言后重跑）

```
python scripts\msg_index.py --lang <L>
python scripts\export_texts.py --lang <L>
```

`export_texts.py` 会整表重写，要保留的译文需要备份；
两张表的功能查看[实现细节/译文与索引](实现细节.md#译文与索引)。

4) 翻译 `input/texts.<L>.csv` 的译文列，遵循下面的字面写法

译文表的格式：

```csv
key,<原文列>,<译文列>,comment
zel_00/1,原文,译文,备注
zel_unit/0/one,原文,译文,备注
```

- 一行对应一条文本
- 打包时只读 `key` 和译文列；原文列自行准备，`comment` 随便写
- 表头
  - 要有 `key` 与译文列
  - 这两列的名字由 `scripts/config.default.json` 里该语言的 `draft_col` / `locale_col` 定
  - 列序随意、忽略多余列
  - 每行的列数要与表头一致（末尾空行也算不符）
- `key`的构成:`<资源>/<条目>[/<字段>]`
  - 资源: 归档内 BMG 名去掉 `.bmg`
  - 条目号: 消息号; 同个消息号重复出现时，后一条补 `#<下标>`
  - 字段名只出现在一个资源有多条文本时（`zel_unit` 的 `one` / `other`，表达单位的单数、复数）
- 文本字面量的特殊规则
  - 换行写 `\n`
  - 其它控制码写 `\xNN`
  - 标签写 `<Tggcccc>`
  - 带数据的标签写 `<Tggcccc:hex>`
- 文件编码 UTF-8

5) 打包

产物：
- `dist\<id>.dusk`

每种方式各自的限制见[实现细节/生成资源](实现细节.md#生成资源)。

1. 从零生成（文本用 own 码位方案 + 字库重渲染）：

```
python scripts\build_bmg.py --lang <L>
python scripts\build_bfn.py --lang <L>
python scripts\verify_texts.py --lang <L>
python scripts\diag_pack.py --lang <L>
python scripts\build_sjis_pack.py --lang <L> --check
python scripts\build_sjis_pack.py --lang <L>
```

2. 改现成素材（文本与字库都直接使用素材内容）：

```
python scripts\sjis_map.py --lang <L>
python scripts\patch_sjis_font.py --lang <L>
python scripts\patch_sjis_text.py --lang <L>
python scripts\build_sjis_pack.py --lang <L> --variant origin
```

3. sjis 码位方案的 open 包（文本沿用现有字库的码位 + 字库重渲染）：

```
python scripts\sjis_map.py --lang <L>
python scripts\build_bmg.py --lang <L> --code-space sjis
python scripts\patch_sjis_font.py --lang <L> --glyph-source open
python scripts\verify_texts.py --lang <L> --code-space sjis
python scripts\diag_pack.py --lang <L> --code-space sjis
python scripts\build_sjis_pack.py --lang <L> --code-space sjis
```
