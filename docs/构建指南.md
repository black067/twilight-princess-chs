# 构建指南

1) 克隆本仓库 `twilight-princess-chs`

2) 自行准备：游戏数据（消息库与两套字库归档）、`assets` 里的 icon/banner（用于 mod 显示）、两套字体文件；译文表由脚本从素材生成，见[实现细节](实现细节.md)「索引与译文表」

- `fonts.fontres`：游戏里画对话正文、菜单、栏位文字的那套字库
- `fonts.rubyres`：游戏里画存档界面、地图菜单楼层与地名、Game Over、对比度页面的那套字库

译文表的格式：

```csv
key,<原文列>,<译文列>,comment
zel_00/1,原文,译文,备注
zel_unit/0/one,原文,译文,备注
```

- 一行 = 一格文本
- 打包时只读 `key` 和译文列；原文列自行准备，`comment` 随便写
- 表头
  - 要有 `key` 与译文列
  - 这两列的名字由 `scripts/config.json` 里该语言的 `draft_col` / `locale_col` 定
  - 列序随意、多余列不管
  - 每行的列数要与表头一致（末尾空行也算不符）
- `key` = `<资源>/<单元>[/<格名>]`
  - 资源 = 归档内 BMG 名去掉 `.bmg`
  - 单元 = 消息号；同一消息号重复出现时，后一条补 `#<下标>`
  - 格名只出现在多格资源上（`zel_unit` 的 `one` / `other`，用于表达单位的单复数形式）
- 文本字面
  - 换行写 `\n`
  - 其它控制码写 `\xNN`
  - 标签写 `<Tggcccc>`
  - 带数据的标签写 `<Tggcccc:hex>`
- 文件编码 UTF-8

3) 翻译

翻译 `input/texts.<L>.csv` 的译文列，注意要遵循文本字面的特殊规则。

4) 打包

```
python scripts\build_bmg.py --lang <L>
python scripts\build_bfn.py --lang <L>
Copy-Item work\<L>\scratch_parts\*.arc work\<L>\sjis_parts\ -Force
python scripts\verify_texts.py --lang <L>
python scripts\diag_pack.py --lang <L>
python scripts\build_sjis_pack.py --lang <L> --check
python scripts\build_sjis_pack.py --lang <L>
```

产物：`dist\<id>.dusk`（三个地区各一份）。另两条路线（就地改写现有素材、sjis 码位空间）见[实现细节](实现细节.md)。
