# 实现细节

主路线是容器与字库都从零生成；备选路线：就地改写现有素材

一次作业由一个`lang`段描述（源素材目录、列名、槽位、元信息），不带 `--lang` 时用 `default_lang`。
中间产物按语言分目录（`work/<lang>/`），同一套脚本可以分别生成多种语言的包；
示例段见 `scripts/config.example.json` 的 `langs`。

## 仓库目录

| 路径 | 内容 |
| --- | --- |
| `scripts/` | 构建与打包管线（Python，只用标准库；外部路径见 `config.example.json`）。字库重渲染 `font_render.py` 走 Windows GDI+，**只支持 Windows** |
| `data/` | 入库的配置表：名字键盘字表、每语言的容器索引、文本资源形状表 |
| `docs/` | 构建指南 / 实现细节 / 发布指南 |
| `tools/` | 配套工具：`dusklight-download/` 拉 dusklight / dusk-cn 的 release、启盘镜像 |
| `assets/` | 上架素材：`icon.png`（299×299）、`banner.png`（1600×457）、`preview-*.png`；lang 段的 `mod.icon` / `mod.banner` 指向它们 |
| `input/` | 素材输入（自备） |
| `dist/` `work/` | 本地产物（成品包 / 中间数据） |

## 素材输入（`input/`）

素材根由顶层 `input_dir` 制定（默认为 `input/`）。

| 路径 | 内容 |
| --- | --- |
| `<lang 的 source>/bmgres.arc.yaz0` … `bmgres99.arc.yaz0` | 10 个消息库：Yaz0 压缩的 RARC，内含 BMG；哪个语言读哪个目录由 `langs.<lang>.source` 定 |
| `input/texts.<lang>.csv` | 译文表：一行 = 一格文本（`export_texts.py` 从该语言的源素材导出，之后只维护它） |
| `<font_source>/fontres.arc.yaz0`、`rubyres.arc.yaz0` | 两套参照字库：Yaz0 压缩的 RARC，内含 BFN（目录缺省 `input/font`） |
| `<font_source>/rodan_b_24_22.bfn`、`reishotai_24_22.bfn` | 同上，解压后（就地改写路线与 `check_cn_coverage.py` 用） |

消息库里的文件名是 `zel_00.bmg` … `zel_08.bmg` 与 `zel_99.bmg`（与引擎 `d_meter2_draw.cpp` 的 `bmg_filename[]` 一致）；
字库归档里的内层名是 `rodan_b_24_22.bfn` 与 `reishotai_24_22.bfn`（与 `mDoExt_initFont0` / `initFont1` 一致）。
条数：`bmgres.arc` 两张表（`zel_00.bmg` 5000 条消息、`zel_unit.bmg` 15 条短串），
`bmgres1.arc` … `bmgres8.arc` 各一张表（1820 / 1351 / 508 / 1606 / 1477 / 1357 / 1173 / 1299 条消息），
`bmgres99.arc` 是 109 字节的空壳。

源文本的编码写在 BMG 头里（`1` = 每字节一个字符，`2` = 2 字节码位，`3` = ShiftJIS）；
tag 的几何随编码变（数值见「容器格式」）。
部件名（`fontres.arc` / `bmgres.arc`）就是打包时写进包内的名字。

**配置表（`data/`）**

| 文件 | 内容 |
| --- | --- |
| `msg_index.<lang>.json` | 容器索引：每个 BMG 的名字、条数、条目尺寸、encoding、消息号列表（`mid1`）、条目属性（去重表 + 游程）、STR1 大小、尾部块 tag 与大小；由 `msg_index.py` 从该语言的源素材现算 |
| `text_resources.json` | 文本资源形状（`messages` / `string_pairs`）与各格的名字 |
| `name_keyboard.json` | 引擎名字键盘（`l_mojiZh`）的 550 个码位 |

**产物（`work/<lang>/`）**

| 路径 | 内容 |
| --- | --- |
| `code_map.json` | 字符 → 码位（容器与字库读同一份） |
| `parts.open.own/`、`parts.open.sjis/`、`parts.open/`、`parts.origin/` | 部件：`bmgres*.arc`、`fontres.arc`、`rubyres.arc`（见「主路线」的目录表） |
| `sjis_map.json` | 就地改写路线的码位映射（`sjis_map.py` 写） |
| `keyboard_aliases.json` | 名字键盘与默认名的别名产物（`diag_pack.py` 拿它核 550 格；sjis 码位空间那份叫 `keyboard_aliases.sjis.json`） |

### 索引与译文表

两张表都从素材现算（一次；换素材或换语言后两条都要重跑）：

```pwsh
python scripts/msg_index.py --lang <L>     # 源素材 -> data/msg_index.<lang>.json
python scripts/export_texts.py --lang <L>  # 源素材 + 索引 + data/text_resources.json -> input/texts.<lang>.csv
```

索引是「要写哪些格子」的账本（导出与打包都读它）；译文表是之后唯一维护的那张表，
`export_texts.py` 整表重写（见「常见坑」）。拿到表之后的翻译与打包见[构建指南](构建指南.md)。

## 配置分层

配置分两层：`scripts/config.example.json` 是完整默认值（路径字段写成 `<占位符>`），
`scripts/config.json` 只写本机差异；两者递归合并（`langs` 段按语言逐键合并），命令行 `--xxx` 再覆盖。

`langs` 里一段 = 一次作业，字段：

| 字段 | 含义 |
| --- | --- |
| `source` | 源素材目录（相对仓库根） |
| `draft_col` / `locale_col` | 译文表的底稿列 / 译文列（打包只读译文列） |
| `default_name_chars` | 要改写成单字节码位的默认名字表（空 = 不改写，见「名字与键盘」） |
| `default_name_cells` | 哪几格按单字节码位写（如 `["zel_00/898", "zel_00/899"]`；文本取自译文表） |
| `input_dir` | 本地素材根（缺省 `input/`）：消息库、参照字库、译文表都在它下面；`font_source` 不给时的默认位置也从它派生 |
| `font_source` | 参照字库目录（缺省 `<input_dir>/font`；顶层可写默认值，lang 段可覆盖） |
| `discs` | **每个盘一项**的替换槽位：`region`（字库目录 `Font<region>`，us/eu/jp）与 `language`（消息目录 `Msg<language>`，uk/us/de/fr/sp/it/jp） |
| `mod` / `mod_origin` | 两个变体的完整元信息（id/name/version/author/description/icon/banner） |

`default_lang` 定不带 `--lang` 时用哪段；配置里有多个语言时必须用 `--lang` 指定。
带 `--lang` 的脚本：`msg_index.py` / `export_texts.py` / `build_bmg.py` / `build_bfn.py` / `sjis_map.py` /
`patch_sjis_*` / `verify_texts.py` / `diag_pack.py` / `build_sjis_pack.py` / `install.py`。
顶层 `fonts` 是默认值，lang 段可以只覆盖要改的字库（游戏里本来就是两套字库，各配 `file`/`em`/`gamma`）；
顶层 `out` 是成品包目录，lang 段也能覆盖。

id 里的 `{region}` 展开成短名（`yiga.zh.hans.<region>` / `yiga.zh.hans.<region>.orig`），
name/description 里的 `{region}` / `{language}` 展开成全称（`United States` / `French`）。
打包按 `discs x 变体` 出包；不带 `--variant` 时只打 `PUBLISHED_VARIANTS`（该语言 3 个地区各一份
`yiga_zh_hans_<region>.dusk`）。

## 主路线：容器与字库从零生成

命令与顺序见[构建指南](构建指南.md)。

部件目录都在 `work/<lang>/` 下，名字 = 变体（`open` / `origin`）+ 码位空间（`own` / `sjis`）：

| 目录 | 内容 | 谁写 |
| --- | --- | --- |
| `parts.open.own/` | open 变体、own 码位空间的中间产物 | `build_bmg.py`、`build_bfn.py` |
| `parts.open.sjis/` | open 变体、sjis 码位空间的中间产物 | `build_bmg.py --code-space sjis`、`patch_sjis_font.py --glyph-source open` |
| `parts.open/` | open 变体的部件目录，`build_sjis_pack.py` 读它；上面两个目录的产物先 `Copy-Item` 归位到这里 | — |
| `parts.origin/` | origin 变体的部件目录（没有中间阶段，直接写这里） | `patch_sjis_font.py`、`patch_sjis_text.py` |

部件名不带槽位（`fontres.arc` / `rubyres.arc` / `bmgres*.arc`），同一个部件要写进各地区的
`Font<region>`、`Msg<language>`，去向由 `build_sjis_pack.py` 按名字前缀决定；一个包里字库与文本
必须同一条路线（码位空间要配套）。

## 备选路线：就地改写现有素材

只改文本与字库块、文件尺寸不变，码位沿用现有字库的那套；保留原字库位图的 `origin` 变体只能走这条
（`--variant origin`）。

```pwsh
python scripts/sjis_map.py                 # 码位映射 → work/<lang>/sjis_map.json
python scripts/patch_sjis_font.py          # 字库：只重排原字库位图 + 默认名/键盘别名 → work/<lang>/parts.origin/
python scripts/patch_sjis_text.py          # 消息重编码（含默认名的单字节码位）→ work/<lang>/parts.origin/
```

`patch_sjis_font.py` 缺省只出 origin 部件。加 `--glyph-source open[:<ttf>]` 会重渲染字形，那是
**sjis 码位空间**那条路线的字库（见下），产物落在 `work/<lang>/parts.open.sjis/`，不会碰
`work/<lang>/parts.open/`（那是从零生成路线归位后的部件目录）。`--em <px>` 换字号。

这条路线的文本取自源素材的原版原文，码位映射与字库读同一份
`work/<lang>/sjis_map.json`：原版字库的码位就是 Unicode 码位，被引擎解析拆坏的那批搬进安全区。
`--variant origin` 打出来的包是 `dist/yiga_zh_hans_<region>_orig.dusk`（包内 id
`yiga.zh.hans.<region>.orig`）。短串表（`zel_unit`）不重编码，具体见「文本表与字面语法」。

## 第三条路线：sjis 码位空间的 open 包

用**译文**（不是原版原文）配**沿用现有字库码位**的字库。部件都落在 `work/<lang>/parts.open.sjis/`
（与从零生成路线分开），打出来的包名与 own 空间那套相同——两者覆盖同一批资源，一次只装一个。

```pwsh
python scripts/sjis_map.py                              # 码位映射（这条路线的基础）
python scripts/build_bmg.py --code-space sjis           # 文本：码位沿用现有字库 → work/<lang>/parts.open.sjis/
python scripts/patch_sjis_font.py --glyph-source open   # 字库：重渲染字形、沿用现有字库码位 → 同一个目录
Copy-Item work\<lang>\parts.open.sjis\*.arc work\<lang>\parts.open\ -Force   # 部件归位到打包目录

python scripts/verify_texts.py --code-space sjis        # 对照译文列：不一致 1 格（见下）
python scripts/diag_pack.py --code-space sjis           # 未正常结束 0 条、缺字 0 次、键盘不符 0
python scripts/build_sjis_pack.py                       # 打包（元信息与 own 空间同一份）
```

`--code-space` 决定验收脚本查哪张期望表/反查表：`own`（缺省）查 `work/<lang>/code_map.json` 与
`work/<lang>/keyboard_aliases.json`，`sjis` 查 `work/<lang>/sjis_map.json` 的 remap 与
`work/<lang>/keyboard_aliases.sjis.json`。

**局限**：这条路线只能画「现有字库的码位表里有的字」——译文里出现现有字库没有的字符时无码位可沿用，
只能按原样写 Unicode 码位，而那种码位的首字节未必是合法 Shift-JIS 前导字节，引擎会把它拆成两个字符。
实测 `zel_unit/5/one`（`秒` = U+79D2，原字库表里没有）就画成 `yÒ`，所以 `verify_texts.py --code-space sjis`
报 1 格不一致。要覆盖全部译文用 own 空间。

## 可调项

- 字体：`fonts.<字库>.file` / `em` / `gamma` 按字库单独配；`fonts.<字库>.ascent` / `descent` / `width` /
  `leading` 改字库的排版度量（代码里的默认值对齐原字库：主字库 `42/6/42/48`、副字库 `43/5/48/48`）；
  `work/fonts/` 下的 `compare_*.png`、`orig_*.png` 是标定对照图
  （`font_render.py` 可单独出试印图，见「校验与排障工具」）。
- 码位空间：`build_bmg.py --code-space own`（默认，自分配，配 `build_bfn.py` 的字库）或
  `sjis`（沿用 `work/<lang>/sjis_map.json` 里现有字库的码位，配 `patch_sjis_font.py --glyph-source open`
  的字库；两者都在 `work/<lang>/parts.open.sjis/`，步骤与局限见「第三条路线」）。`verify_texts.py`
  与 `diag_pack.py` 用 `--code-space` 跟同一套。
- 作业段：`--lang <名字>` 选 `langs` 里的一段（缺省 `default_lang`）；加一段新语言 = 在 `config`
  里多写一个 lang 段（`source` / `draft_col` / `locale_col` / `discs` / `mod` / `mod_origin`），
  再跑一次 `msg_index.py --lang <名字>` 与 `export_texts.py --lang <名字>`。
- 槽位：lang 段的 `discs` 里每个盘一项 `region`（决定字库目录 `Font<region>`）与 `language`（决定消息目录 `Msg<language>`）——
  换 dump 或只保某个地区时改这里；`--region <us|eu|jp>` / `--variant <open|origin>` 可只跑一个。
- 输出：`out` 决定成品包目录（默认 `dist`，lang 段可覆盖）；两个变体的 id/name/description 分别写在
  lang 段的 `mod` / `mod_origin`（id 里的 `{region}` 展开成短名，必须带它，否则各地区包同名互盖）。

## `install.py` 行为

```pwsh
python scripts/install.py --lang <L> --region <us|eu|jp>   # --list 只看现状
```

- 拷 `dist/<id>.dusk` 到 `mods_dir`，并把 `game_config` 里该包的 `mod.<id>.enabled` 置 `true`；
  两个路径由 config 的 `mods_dir` / `game_config` 或 `--mods-dir` / `--game-config` 指定
  （dusklight 2.x 是 exe 同级的 `mods/` 与数据目录下的 `config.json`，dusk-cn 是 `<游戏目录>/data/` 下的那两个）。
- 会**删掉其他地区与其他变体的包**（它们覆盖同一批资源），并关掉历代旧包的开关。
- 会提示同作者的其他 mod 是否还开着（资源重叠）。
- 装哪个由 `--lang` / `--region <us|eu|jp>` / `--variant <open|origin>` 决定（`--region` 不给时只在配置里
  恰好一个地区时可用）；`--list` 只看现状；`game.language` 仍需自己设。
- 只动当前语言那一套包：其他语言（别的 lang 段）的包不碰——若两个语言的槽位重叠，自己确认没同时启用。

## 容器格式

**BMG（消息库）**

- 头 0x20 字节：`MESG` + `bmg1` + u32 文件大小 + u32 段数 + u8 encoding + 15 字节填充；
  文件大小**不含**尾部的 `FLW1` / `FLI1`。
- 段自 0x20 起、按 0x20 对齐：`INF1`（条目表）/ `DAT1`（文本）/ `MID1`（消息号列表）/ `STR1`，
  其后可跟 `FLW1` / `FLI1`（消息流脚本，没有正文文本）。
- `INF1` 头 8 字节 = 条数(u16) + 条目尺寸(u16) + 4 字节填充；条目 = u32 DAT1 偏移 + u16 消息号 +
  u16 event_label_id + 12 字节属性（speaker、box_kind、draw_type、box_position、item_no、line_alignment、
  speaker_mood、camera_attr、talk_anim、face_anim、lines_per_page、padding）。
  引擎按条目的**消息号**查消息，属性决定说话人/框样式等，所以两样都不能省。
- `MID1` 子头 8 字节 = 条数(u16) + form/supplement(u16) + 4 字节填充，其后是每条消息的消息号（u32）。
- `STR1` 是字符串池（本项目的归档里是 2 字节码位、`0000` 收尾），短串表靠它（见「文本表与字面语法」）。
- 消息正文以编码的 `0` 字符收尾；引擎读到第一个 `0` 就当作消息结束。
- `encoding` 属文件自声明（头 0x10 字节），读取层按它切字符：`1` = 每字节一个字符，`2` = 2 字节码位，
  `3` = ShiftJIS（前导字节吃 2 字节），不绑语言槽；本项目的消息容器一律写成 `3`。
  同一文件里的字符串池（`STR1`）也是这个编码。
- tag 几何跟编码走：marker 是当前宽度的 `0x1A`（2 字节码位的归档里是 `00 1A`，单字节归档里是 `1A`），
  紧跟 1 字节 `size` + 3 字节 tag id + 数据；**步进 = `size`**，payload = `size - 4 - marker 宽度`
  （实测中文素材 `input/msg` 与美版素材 `input/msg_us` 的 `bmgres3` 各 507 / 508 条精确落在终止符，其它口径明显更差）。
  引擎侧不同：marker 只有 1 字节，所以写包时 `size = payload + 5`。

**BFN（位图字体）**

- 头 0x20 字节：8 字节魔数 + u32 文件大小 + u32 块数 + 16 字节填充。
- 块：`INF1`（`fontType` = u16 @块+0x08、宽度表）/ `WID1`（可选）/ `GLY1`（字形）/ `MAP1`（码位映射）。
- `MAP1`：method@+0x08、startCode@+0x0A、endCode@+0x0C、numEntries@+0x0E、表@+0x10；
  method 3 = 有序的 `{u16 码位, u16 字形索引}`（引擎按码位二分查找），method 0 = 恒等映射。
- `GLY1`：startCode@+0x08、endCode@+0x0A、cellW@+0x0C、cellH@+0x0E、texSize@+0x10、fmt@+0x14、
  rows@+0x16、cols@+0x18、texW@+0x1A、texH@+0x1C；字形数据是 GX 平铺（tiled）格式，重排时必须保持平铺。
- `WID1`：每槽 2 字节（前导偏移, 前进宽度），单位是格宽的 1/48；没有 `WID1` 时引擎一律用 `INF1.width`
  当前进宽度（ASCII 会变成全角宽）。
- 字库必须是**单页**：页数按 `rows × cols` 推、拼成一张纹理，页数多了拼合高度爆表、建纹理失败，
  所以 `rows × cols` 要容下全部字形。
- 从零生成（`build_bfn.py`）时字形槽自己排：`0x00..0x5F` 给 ASCII（`MAP1` method 0 恒等，槽 = 码位 − 0x20），
  其余码位按码位升序接在后面；`WID1` 前进宽度 = 字体前进宽度（em）× `INF1.width`，前导偏移按墨迹居中。
  引擎按「最小 startCode」判断要不要把半角 ASCII 换成全角码位（`halftofull`，见 `JUTResFont::getFontCode`），
  `MAP1` 里有覆盖 `0x20..0x7F` 的段就不换；同时又照那张表把那 95 个全角码位别名到同一批 ASCII 字形，
  免得哪条路径先转换过就查不到字形。

**RARC（归档）**

- 头 0x20：`RARC` + 文件长度 + header_length + file_data_offset + …，信息块在 header_length 处。
- 节点表 / 文件表 / 字符串表的偏移相对信息块起点；`data_offset` 相对 `header_length + file_data_offset`，
  每条数据按 0x20 对齐。
- **文件项在磁盘上占 0x14 字节**（末 4 字节是主机端 data 指针字段，写 0）；写成 0x10 会让后续条目错位，
  按名取不到文件。
- 字符串表开头要先登记 `"."` / `".."` 两个占位项；名字哈希 `h = (tolower(ch) + h * 3) & 0xFFFF`（初值 0）。

## 文本表与字面语法

`input/texts.<lang>.csv` 是译文（该语言）的唯一来源，打包只读 `key` 与译文列 `locale_col`（其余列不参与打包）。
两个列名与源素材目录由 lang 段定；`export_texts.py` 从源素材导出它（列：`key,<draft_col>,<locale_col>,comment`，
导出即整表重写），`build_bmg.py` 读它；两边的格集合由
`data/msg_index.<lang>.json` + `data/text_resources.json` 决定，`text_resources.py` 负责枚举与拆解。

- 一行 = BMG 里的一格文本；`key` = `<资源>/<单元>[/<格名>]`，资源名是 BMG 文件名去掉 `.bmg`。
  消息表的单元是消息号，同一消息号出现两次时后一条补 `#<下标>`（原归档里真有这种：`zel_04` 有 1607 条、
  末条与第 613 条同号且文本为空，引擎只会查到前一条）。
- 形状：
  - `messages`：一格 = `DAT1` 正文，单元 = 消息号，如 `zel_03/5000`；
  - `string_pairs`：条目里的两个 u16 字段是 `STR1` 的**字节偏移**，单元 = 条目下标，
    如 `zel_unit/0/one`、`zel_unit/0/other`（同一句量的单数形与复数形）——
    引擎按数值是否等于 1 选格，拼成「数字 + 空格 + 标签」插进消息串。
- 字面语法

  | 写法 | 含义 |
  | --- | --- |
  | 普通字符 | 原样 |
  | `\n` | 换行（U+000A） |
  | `\xNN` | 其它控制码 |
  | `<Tggcccc>` | 标签（gg = 高字节） |
  | `<Tggcccc:hex>` | 带数据的标签，hex = payload 字节，如 `<T000036:001e>` |

- 打包时有意改写：标签 `060005`（装饰性 ※）换成字面 `※`；默认名（`zel_00/898`、`zel_00/899`）
  写成单字节码位 `A1..A5`。
- 短串表的两格按正文同一套编码写（ASCII 与换行 1 字节、其余查码位表后 2 字节）—— 池串会被引擎
  直接拼进消息串、随消息一起解，用别的编码字库就查不到。open 路线（`build_bmg.py`）重建 `STR1`
  池；就地改写（`patch_sjis_text.py`）只重编码 `DAT1` 正文，池里仍是原档的 2 字节码位，
  `zel_unit` 那 15 条单位（`one` / `other`）会画错（本质上是因为欧版和中文版的渲染逻辑不同）。
- 表与包对不上会直接报错：key 缺、多、重复，或字面串读不回同一串 token（真的带反斜杠、
  或形如 `<T……>` 的文本）都退出，不静默跳过也不转义。

## 码位分配

译文用到的字由 `codes.py` 分配码位（`build_bmg.py` 写 `work/<lang>/code_map.json`，字库读同一份），约束：

1. 前导字节是合法 Shift-JIS 前导（`0x81..0x9F` / `0xE0..0xFC`）；
2. 码位 ≥ `0x8800`，否则被引擎的 `change1ByteTo2Bytes` / `changeKataToHira` 改写；
3. 尾字节也是合法 Shift-JIS 尾字节（`0x40..0x7E` / `0x80..0xFC`，即不是 `0x7F`）。几处引擎代码**逐字节**扫串：
   尾字节 `0x00` 会被当成消息结束，`getStringKanji` / `getStringKana` 把 `0x1A` 当标签按长度跳步，
   `J2DPrint::parse` 把 `0x1B` 当控制码前缀——踩到就会被拆坏（症状：整串文字只剩半边）；
4. 落在 JIS X 0208 未定义区（`0xEAA5..0xEFFC` / `0xF040..0xF9FC`）：菜单资源与引擎字符串都是标准字符，
   避开它们才不会出现「一个码位两种含义」（症状：名字框的空格位画出游戏自带数据里的字）；
5. 不与 `data/name_keyboard.json`（引擎名字键盘自己会查的表）撞车。

ASCII 用原码位，默认名的单字节码位用 `0xA1..0xA5`，键盘与图标码位按原样带过。

## 名字与键盘

- 默认名来自消息 `0x381`（`林克`）与 `0x382`（马，`伊波娜`）；这两个号是引擎侧的 INF1 下标，
  对应译文表的 `zel_00/898` 与 `zel_00/899`（消息号 = 下标 + 1）。名字输入按**单字节**取字，
  所以默认名用单字节码位承载汉字：向 `MAP1` 追加 `0xA1..0xA5 → 林 克 伊 波 娜` 的别名
  （指向既有字形槽，不新增槽、不重渲染、不改 `WID1`），这两格写成原始字节 `A1 A2` / `A3 A4 A5`，
  两个变体都建。代价：一个字占一个字符位（名字上限 8 个汉字）；玩家自己改名时键盘仍只有拉丁字母。
  字表在 lang 段的 `default_name_chars`（哪个语言需要才写；不写就不动默认名，别的语言的原样保留），
  要按单字节写的是哪几格在 lang 段的 `default_name_cells`（按译表格子键写，名字文本不从配置来，直接取译文表那一格）。
  默认段（`langs.zh-Hans`）的取值 = `林克伊波娜` + `["zel_00/898", "zel_00/899"]`。
- 中文输入键盘的表（550 格）由 `data/name_keyboard.json` 提供，逐格建 `MAP1` 别名：
  从零生成字库（`build_bfn.py`）把 550 格全部渲染；就地改写（`patch_sjis_font.py`）只能用现有字库的
  字形槽，于是 393 格直接用、55 格换成简体写法（对照表 `NAME_VARIANT`）、102 格两种写法都没有，
  只能指向空白字形（格子显示为空、仍可按）。
- 上游 EU 键盘表里原字库缺的 51 格（`PAL_KEY_CODES`，含 Œ/œ）同样处理，
  **所以「中文键盘整表可用」只对 open 变体成立**。
- 补全结果落在 `work/<lang>/keyboard_aliases.json`（`direct` / `variant` / `added` / `blanked` / `pal` / `name_default`），
  数字以它为准（从零生成时 `added` 就是全部 550 格）。沿用现有字库码位那条路线（
  `patch_sjis_font.py --glyph-source open`）写的是 `work/<lang>/keyboard_aliases.sjis.json`，两张表不混用。
  新增槽位会抬高 `GLY1.endCode`（上限 = `rows × cols`），单页布局不变。
- 中文键盘本身是 `snnh/dusk-cn` 分支的功能（`game.enableChineseNameKeyboard`）；上游 dusklight 没有该开关，
  名字只能打拉丁字母，但默认名照样显示中文（靠上面的单字节别名）。
- 键盘按钮文案是消息 `0x38B/0x38C/0x388/0x38E`。

## 校验与排障工具

带 `--lang` 的脚本都在 lang 布局下跑：部件取 `work/<lang>/…`，对照 `input/texts.<lang>.csv`，
索引取 `data/msg_index.<lang>.json`。

- `msg_index.py`：从 lang 的源素材现算容器索引（条数 / entrySize / `mid1` / 条目属性 / `str1Size` /
  `bmgSize` / 尾部块）→ `data/msg_index.<lang>.json`；新增语言段或换素材后必跑。
- `diag_pack.py` 主判据：按引擎路径解码包内全部文本，核字库覆盖与键盘每一格，应输出「未正常结束
  0 条、缺字 0 次」与「名字键盘 … 不符 0」。`--variant <open|origin>` 选部件；键盘补全只对 open 成立，
  其余变体跳过该项。`--code-space <own|sjis>` 选键盘期望表（`own` = `keyboard_aliases.json`，
  `sjis` = `keyboard_aliases.sjis.json`）。
- `verify_texts.py` 主判据之二：打好的部件 vs `input/texts.<lang>.csv` 逐格比。
  `--variant <open|origin>` 决定对照列（open = 译文列，origin = 底稿列）；
  `--code-space <own|sjis>` 决定码位反查表。期望值：open + own 报 **0 格**；sjis 空间报 **1 格**
  （`zel_unit/5/one`，原字库码位表里没有 `秒`，见「第三条路线」）；origin 报 **30 格**（短串表不重编码）。
- `material.py` 是 `<input_dir>/` 的唯一读取层（消息库按 lang 的 `source`，字库按 `font_source`），缺目录直接退出；
  `text_resources.py` 枚举 `<资源>/<单元>[/<格名>]` 并给消息键去重。
- `check_cn_coverage.py`：译文用到的字符 vs 参照字库 `rodan_b_24_22.bfn` 的 `MAP1`，报「原字库画不出」的字符
  （保留原字库位图的 `origin` 变体看它；控制码不算缺字）。
- `dump_bfn.py` 转储字库块头；`cmp_msg.py` 逐字节对照包内文本与源素材里的归档。
- `find_syms.py` 扫 exe 裸字符串（dusklight.exe 没有带地址的符号表，反查调用方要靠引擎源码）。
- `font_render.py` 可单独标定与试印：
  `python scripts/font_render.py --font fontres --ttf work/fonts/NotoSansCJKsc-Regular.otf --em 46 --png work/fonts/render_fontres.png`；
  与 `work/fonts/compare_*.png`、`orig_*.png` 对照挑 `em` / `gamma` / 字重。

## 常见坑

- 素材：lang 段的 `source` 目录齐了才能跑 `export_texts.py`，参照字库目录（`font_source`）齐了才能跑就地改写路线；
  `material.py` 找不到目录会直接退出。
- 索引是按语言的：新增语言段、换了素材、换了地区槽位内容后都要重跑 `msg_index.py --lang <名字>`（
  入口会报条数与文件数，与源素材对不上时导出/打包会直接报错）。
- 译文表要与索引对得上：`input/texts.<lang>.csv` 缺 key、多 key、key 重复、行列数与表头不符，`build_bmg.py` 都直接报错。
- 键空间：消息表的 key 是 `<资源>/<消息号>`，同一消息号出现两次时后一条补 `#<下标>`（原归档里真有这种，
  后一条引擎查不到）。
- 译文表是导出脚本的目标：`export_texts.py` **整表重写**（译文列与底稿列都落成源素材原文），要保留的译文先备份。
- 顺序：先出部件（open 走 `work/<lang>/parts.open.own/` 或 `parts.open.sjis/` → 归位到 `work/<lang>/parts.open/`，
  origin 直接写 `work/<lang>/parts.origin/`），再 `build_sjis_pack.py`；缺部件直接退出并提示该跑哪个脚本，
  `--check` 模式不需要部件。
- `.dusk` 只是个 zip：`mod.json` + `overlay/<光盘内路径>`（或 `textures/`）；mod 自己的图（`icon`/`banner`）
  放包内 `res/`，config 里填本地 PNG 路径，打包时由 `build_sjis_pack.py` 放进去。
- 各地区的包内容只有 `overlay` 目录名不同（`Font<region>` / `Msg<language>`），同一批文件只能装一个。
- 中文键盘与键盘补全只对 open 变体成立。
- 换过码位空间后，旧存档里的名字是旧码位，会显示成错字：新建存档或重输一次名字。
