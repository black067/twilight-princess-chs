# 管线复现

从 `cn/` 素材到 `dist/*.dusk` 的完整步骤（README 的「快速开始」是精简版）。
主路线是容器与字库都从零生成；就地改写现有素材是备选路线（见文末）。

## 素材输入（`cn/`）

| 路径 | 内容 |
| --- | --- |
| `cn/msg/bmgres.arc.yaz0` … `bmgres99.arc.yaz0` | 10 个消息库：Yaz0 压缩的 RARC，内含 BMG |
| `cn/texts.csv` | 译文表：一行 = 一格文本（`export_texts.py` 从 `cn/msg/` 导出，之后只维护它） |
| `cn/font/fontres.arc.yaz0`、`cn/font/rubyres.arc.yaz0` | 两套字库：Yaz0 压缩的 RARC，内含 BFN |
| `cn/font/rodan_b_24_22.bfn`、`cn/font/reishotai_24_22.bfn` | 同上，解压后（就地改写路线与 `check_cn_coverage.py` 用） |
| `cn/text/*.txt` | 同一批消息的可读文本，供人读与校对（管线不读） |

部件名（`fontres.arc` / `bmgres.arc`）就是打包时写进包内的名字。
`material.py` 是唯一的读取层，缺目录直接退出。

## 配置分层

配置分两层：`scripts/config.example.json` 是完整默认值（路径字段写成 `<占位符>`），
`scripts/config.json` 只写本机差异（路径字段）；两者递归合并，命令行 `--xxx` 再覆盖。
`discs` 是**每个盘一项**的替换槽位：`region`（字库目录 `Font<region>`，us/eu/jp）与
`language`（消息目录 `Msg<language>`，uk/us/de/fr/sp/it/jp），默认美版 `us`/`us`、欧版 `eu`/`fr`、日版 `jp`/`jp`；
字体按字库分开配 `fonts.fontres` / `fonts.rubyres`（各 `file`/`em`/`gamma`）——游戏里本来就是两套字库。
两个变体各有自己完整的一段元信息：`mod`（开源字体版）与 `mod_origin`（保留原字库位图，`--variant origin`）——
id/name/description 各写各的，id 里的 `{region}` 展开成短名（`yiga.zh.hans.<region>` /
`yiga.zh.hans.<region>.orig`），name/description 里的 `{region}` / `{language}` 展开成全称
（`United States` / `French`）。
打包按 `discs x 变体` 出包；不带 `--variant` 时只打 `PUBLISHED_VARIANTS`（3 个地区各一份
`yiga_zh_hans_<region>.dusk`）。

## 完整步骤

```pwsh
# 0) 准备开源字体（重渲染用；两套字库可分别替换）
#    work/fonts/NotoSansCJKsc-Regular.otf   思源黑体 / Noto Sans CJK SC（OFL-1.1）
#    work/fonts/LXGWWenKai-Regular.ttf      霞鹜文楷（OFL-1.1）
#    配置里按字库分开指定：fonts.fontres.file / fonts.rubyres.file 与各自的 em / gamma

# 1) 译文表：从 cn/msg/ 导出一次，之后改译文只动 cn/texts.csv
python scripts/export_texts.py             # 列：key,cn,zh-Hans,comment；写法见技术备忘「文本表与字面语法」

# 2) 容器与字库从零生成
python scripts/build_bmg.py                # 消息容器（读 texts.csv，顺带写 work/code_map.json）
python scripts/build_bfn.py                # 两套字库（读同一份码位表）→ work/scratch_parts/
Copy-Item work\scratch_parts\*.arc work\sjis_parts\ -Force   # 部件归位到打包目录

# 3) 验收与打包
python scripts/verify_texts.py             # 部件 vs texts.csv 逐格比：不一致 0 格
python scripts/diag_pack.py                # 引擎路径验收：未正常结束 0 条、缺字 0 次
python scripts/build_sjis_pack.py --check  # 只校验 mod.json 元数据、不写包（上传前先跑）
python scripts/build_sjis_pack.py          # 打包：每个盘一份（不安装）；--region us 可只跑一个
python scripts/install.py --region us      # 安装：拷包 + 开关（--list 只看现状）
```

每个变体一个部件目录：open 是 `work/sjis_parts/`，origin 是 `work/sjis_parts.origin/`，两条路线各写各的。
部件名不带槽位（`fontres.arc` / `rubyres.arc` / `bmgres*.arc`），同一个部件要写进各地区的
`Font<region>`、`Msg<language>`，去向由 `build_sjis_pack.py` 按名字前缀决定；一个包里字库与文本
必须同一条路线（码位空间要配套）。

## 备选路线：就地改写现有素材

只改文本与字库块、文件尺寸不变，码位沿用现有字库的那套；保留原字库位图的 `origin` 变体只能走这条
（`--variant origin`）。

```pwsh
python scripts/sjis_map.py                 # 码位映射 → work/sjis_map.json
python scripts/patch_sjis_font.py          # 字库：重渲染字形并补键盘格
                                           #   走 config 的 glyph_source；--glyph-source original 只出 origin（回归对照），
                                           #   --glyph-source open:<ttf> 换字体文件，--em <px> 换字号
python scripts/patch_sjis_text.py          # 消息重编码（含默认名的单字节码位）→ work/sjis_parts.origin/
```

这条路线的文本取自 `cn/msg/` 的原版原文，码位映射与字库读同一份
`work/sjis_map.json`：原版字库的码位就是 Unicode 码位，被引擎解析拆坏的那批搬进安全区。
`--variant origin` 打出来的包是 `dist/yiga_zh_hans_<region>_orig.dusk`（包内 id
`yiga.zh.hans.<region>.orig`）。短串表（`zel_unit`）不重编码，具体见[技术备忘](技术备忘.md)
「文本表与字面语法」。

## 可调项

- 字体：`fonts.<字库>.file` / `em` / `gamma` 按字库单独配；`fonts.<字库>.ascent` / `descent` / `width` /
  `leading` 改字库的排版度量（代码里的默认值对齐原字库：主字库 `42/6/42/48`、副字库 `43/5/48/48`）；
  `work/fonts/` 下的 `compare_*.png`、`orig_*.png` 是标定对照图
  （`font_render.py` 可单独出试印图，见[技术备忘](技术备忘.md)）。
- 码位空间：`build_bmg.py --code-space own`（默认，自分配）或 `sjis`（沿用 `work/sjis_map.json` 里现有字库的码位）。
- 槽位：`discs` 里每个盘一项 `region`（决定字库目录 `Font<region>`）与 `language`（决定消息目录 `Msg<language>`）——
  换 dump 或只保某个地区时改这里；`--region <us|eu|jp>` / `--variant <open|origin>` 可只跑一个。
- 输出：`out` 决定成品包目录（默认 `dist`）；两个变体的 id/name/description 分别写在 `mod` / `mod_origin`
  （id 里的 `{region}` 展开成短名，必须带它，否则各地区包同名互盖）。

## `install.py` 行为

- 拷 `dist/<id>.dusk` 到 `mods_dir`，并把 `game_config` 里该包的 `mod.<id>.enabled` 置 `true`；
  两个路径由 config 的 `mods_dir` / `game_config` 或 `--mods-dir` / `--game-config` 指定
  （dusklight 2.x 是 exe 同级的 `mods/` 与数据目录下的 `config.json`，dusk-cn 是 `<游戏目录>/data/` 下的那两个）。
- 会**删掉其他地区与其他变体的包**（它们覆盖同一批资源），并关掉历代旧包的开关。
- 会提示同作者的其他 mod 是否还开着（资源重叠）。
- 装哪个由 `--region <us|eu|jp>` 与 `--variant <open|origin>` 决定（不给时只在配置里恰好一个地区时可用）；
  `--list` 只看现状；`game.language` 仍需自己设。

## 常见坑

- 素材：`cn/msg/` 齐了才能跑 `export_texts.py`，`cn/font/` 齐了才能跑就地改写路线；
  `material.py` 找不到目录会直接退出。
- 译文表要与索引对得上：`cn/texts.csv` 缺 key、多 key、key 重复、行列数与表头不符，`build_bmg.py` 都直接报错。
- 顺序：先出部件（open 走 `work/scratch_parts/` → `work/sjis_parts*/`，origin 走 `work/sjis_parts.origin/`），
  再 `build_sjis_pack.py`；缺部件直接退出并提示该跑哪个脚本，`--check` 模式不需要部件。
- `.dusk` 只是个 zip：`mod.json` + `overlay/<光盘内路径>`（或 `textures/`）；mod 自己的图（`icon`/`banner`）
  放包内 `res/`，config 里填本地 PNG 路径，打包时由 `build_sjis_pack.py` 放进去。
- 各地区的包内容只有 `overlay` 目录名不同（`Font<region>` / `Msg<language>`），同一批文件只能装一个。
- 中文键盘与键盘补全只对 open 变体成立。
- 换过码位空间后，旧存档里的名字是旧码位，会显示成错字：新建存档或重输一次名字。
